# Overlays in detail

Moved out of [CLAUDE.md](../CLAUDE.md) so it loads only when you work on this area. CLAUDE.md keeps the rules that bite from anywhere else; read them there too.

## Motion helpers

**Motion is the layout's, never the pack's.** `overlay.css` holds the vocabulary (`--ease-out` for anything arriving **and** anything leaving — an exit on it answers at once and is ~97% gone half-way, so two states never read on top of each other; there is no `--ease-in` — `--ease-spring` for the clip toast; `--enter-*` for the entrances), and `Overlay.motion.ease()` reads the same curves, so CSS and script can't drift apart. **`--motion-tempo` (3; the test sandbox can't read it and uses `TEMPO_FALLBACK`, 1.5) sets the speed of all of it**: every CSS duration is `calc(… * var(--motion-tempo))` and every script duration goes through `Overlay.motion.ms()`, so one number slows or quickens the whole broadcast. Dwell times (the side panel's 20s, the toast's hold, the bracket tour's page holds) aren't animation speed and ignore it. Things arrive by rising a few px, settling and pulling into focus from a slight blur; they leave on the same curve, quickly. These helpers do every show/hide:

- **`Overlay.swap(el, key, render, { motion })`** — out → render → in, only when `key` changed. `lift` — the one text motion, `Overlay.motion.TEXT` (out up 6px + blur 3, 160ms; in from 8px below + blur 4, 480ms), which `presence()`, the character icon and the side panel's rows also use. A change that lands while the old content is still leaving doesn't restart anything: the exit draws the newest render when it ends, so two quick edits are one swap.
  - **`Overlay.draw(el, key, render)`** — the same draw, now and unanimated, remembering `key` so a later `swap()` animates only a real change. For content rebuilt where it can't be seen (the side panel's `renderCrew`); text that changes on screen goes through `swap()`.
- **`Overlay.reel(el, value, build, { clip })`** — a number (the score, a crew's stocks) turning like a slot-machine reel: the old and new values move together by the clipping box's height, up for a bigger number and down for a smaller one, through the values in between (up to 7 cells). No fade, the clip is the exit. An invisible hold keeps the element's size. Interrupted, it snaps to the value it was heading for and turns again; cancelled from outside, it settles on its value.
- **`Overlay.presence(el, on, { hiddenClass = "empty", onHidden })`** — a chip, pill or card that comes and goes whole. It moves exactly like a swap's two halves (`TEXT`): out upward, in from below, no scale. It animates out *before* the class goes on (the stylesheet's `display`/`visibility` hiding is reached, not cut to); a hide overtaken by a show never applies its class or `onHidden`. `Overlay.text(…, { emptyOn })` uses it, so the pronoun chip and best-of pill leave still showing their old text.
- **`Overlay.glide(...nodes)`** — content pushed aside slides instead of jumping (FLIP). The runtime measures every registered node around each layout change it makes (a swap's draw, `presence()`'s class, a reel's width) and slides whatever moved from where it was drawn, in `TEXT`'s entrance time. The slide is `left`/`top` on a relatively positioned box (`glide()` sets `position: relative`), not a transform: Chromium 103 has no `translate` property, and a transform slide would be replaced by any swap or presence on the same box. The scoreboard's name is three pieces for it — sponsor, tag, [L] — so a sponsor or [L] comes and goes on its own (`presence`), a new tag swaps, and the tag slides over for them and for the character icon (`.character_container` is `width: auto`, so the icon arriving narrows the name).
- **`Overlay.motion.pose(rest, { x, y, scale, blur, opacity })`** — one keyframe on top of `restOf(el)`, for a page's own animations (the side panel's rotation, which commits only opacity so a logo's CSS filter stays the stylesheet's).
- **`Overlay.motion.play(el, frames, opts)`** — `el.animate()` for poses, and what every pose goes through (swap, presence, the stats popup's `animate()`, the side panel's cascades). **Chrome composites no animation with a `blur()` in its filter**, and that takes the transform and opacity riding with it to the main thread; `play()` gives the blur an animation of its own (same timing; cancelling or finishing the returned move does the same to it) and drops a filter that's the same in every keyframe, so the move runs on the compositor. Calling `el.animate()` with a pose puts the whole thing back on the main thread. `ms()` and `ease()` read their tokens once (each read was a forced style recalc).

`tests/overlay-motion.test.js` pins that they end on the right content, that every exit is the text motion, and that the reel turns the right way.

## Scoreboard

- **Scoreboard** (`/o/scoreboard`, `/o/scoreboard/players`) — names, prefixes, pronouns, live characters, scores, round, best-of, [L]. In a crew battle the crew's name is a chip on the inner end of the pronoun row (under the score), shown only with someone in (`/o/scoreboard` only — the players bar has no chips). The round card holds the round alone, one line that shrinks to fit (`fitText`). The best-of is a pill between the player cards, styled as the side panel's tournament-name header, on `/o/scoreboard` only (the players bar shows none); a best-of of "None" hides the pill. The live character and costume come from the store. The players bar's logo stands on the round card and **rises out of it**: it sits behind the card (`z-index: 0` under `.stage`), a mask held on the card's line by the same `--logo-y` as the travel hides anything below, and it starts with the card on the cards' own fade, blur, time and curve. It is two layers — `.logo` animates, `.logo-art` carries the artwork and the pack's `--logo-filter` — because an entrance blur and Salty Suite's `invert(1)` on one element can't interpolate and flip halfway. While the stats popup is up the logo sinks back into the card (see The stats popup). On `/o/scoreboard/players` the bar's drop shadow is on `.bar` (the body's box), not the body, so the embedded popup's frame is neither shadowed nor re-filtered every frame.

## Bracket

- **Bracket** (`/o/bracket[?view=]`) — laid out by `bracket/layout.js` (pure, and loaded by the page, the dock and Node alike: a column per round, each set centred on its feeders, SVG connectors, the winner's path in the accent, losers drop-ins tagged "from W-R2" instead of drawn). **Nothing pans.** One tree on one canvas is mostly empty (cards cover 18–25% of a 51-player board: the busiest round sets the height, the later rounds sit in a triangle of nothing), so a view that doesn't fit at the legibility floor (~22px names, scale 0.79 of the 1824×912 viewport — `layout.VIEWPORT`, pinned to `bracket.css`) is first **pruned** (per side, rounds past the next one with anybody in it go; a view that fits whole, like Top 8, keeps its empty future) and then cut into **pages**: round bands laid out on their own, a too-tall band wrapped **k-up** (split between subtrees, side by side — no connector inside a page is ever cut; only the line back to the previous band goes), short winners and losers bands stacked on one page, fewest pages first. HA #50 (51 entrants) is 4 pages at 0.79–1.0 where it was 8 screens of pan. Three modes, from the store's `bracketShot` (`bracket-director.js`): **tour** (pages in turn, from the action; dots under the title fill over each hold; the title stays the pool, the subtitle the tournament · event), **page** (held until Auto), **board** (the classic connected board, pruned, steered from the dock: moves settle on a column edge / the gap above a card, zoom steps are whole-column fits down to the floor, an **Overview** fits it whole with the live sets glowing; round headers pin to the top edge; no minimap on stream — that's the dock's; a near move glides, a far one crossfades). **Up Next** (`?view=upnext` or the dock's key) is every live or ready set in the event as the bracket's card under a round · pool header and an On Stream / Live / Ready chip, in a grid scaled up to 1.4× when there are few and paged when there are many; no Board. `?view=` pins a source to a view, which then tours its own pages. A switch goes in sequence: the old layer fades out (all but gone half-way), then the new board cascades in left to right — each card and round header settles in from the left on a delay set by its on-screen x (one speed for every board, starting at its leftmost card), and each connector draws along its own path (a `stroke-dashoffset`, from `data-from-x`/`data-to-x` on the path) out of the card it leaves once that card has mostly settled, into the card it joins as that one arrives; nothing blurs (the layers are most of the canvas). A data change redraws in place.

## Highlights

- **Highlights** (`/o/highlights`) — the replay-scene frame, **decoration only** (nothing knows which clip VLC is playing). Reads no state; reveals itself, and its socket only follows a theme switch. Each frame is one div whose **`border` is the plate** (`box-sizing: border-box`, so the padding box is the window and the footage shows through; `mask-composite` isn't safe in OBS). Geometry is `:root` variables that must equal the OBS source transforms, settable from the url: `?clip=x,y,w,h`, `?cam=y,w,h` (the cams share it — their centres must sit on the clip's line), `?camx=leftX,rightX`, `?pad=`; blank components are skipped. Cams flush to the canvas edge **bleed** off it (squared corners; the border stays declared — zeroing it would slide the hole by `--pad`). Each cam plate is open toward the clip and extends to meet it (`--join-l/-r`, derived with `max(0px, …)`); on the open side the border goes to 0, the corners square and all three shadow layers drop to three sides, or a gold hairline appears where the rail was. **`?guides=1`** outlines each hole with its *measured* rect (minus the overhang), which is the alignment check. The scrim is four edge bands, never a full-canvas wash (a browser source paints over every source beneath it). Keep `--title-gap` non-zero. The sheen is behind `@supports (background-clip: text)`.

## Side panel

- **Side panel** (`/o/side-panel[?panel=<id>]`) — 611×1080 beside the cam: four background bands, two floating cards, a transparent 587×330 cam cutout (`.cam-overlay` rounds it with an outward spread shadow). The header shows the tournament name from the store. The bottom card rotates (`PANEL_INTERVAL` 20s) through `logo-primary`, `player-1`, `player-2`, `recent-sets`, `last-game`, `logo-sponsor`, `set-recap`, `completed-sets`; doubles drops the player cards and head-to-head.
  - **The stats cards** (`last-game`, `set-recap`) hold **25s** (`PANEL_HOLD`; the reel 6s a callout). Every size in their stylesheet is a multiple of `--k`, which `scaleCard()` sets to the largest (0.8–1.4) that fits the card, so a card with less to say says it bigger; a callout is its title, the number, its line across the box, and whose it is under that. Last Game leaves the set to Set Recap: no set numbers, and no callout marked `span: "set"` (a streak). They draw the stats popup's `setStats` (no request of their own). **Last Game takes the next of three looks each time it comes on screen** (`GAME_LOOKS`: story, reel — the callouts one at a time on a 6s timer that stops itself once the card is off — and box), chosen in the rotator's `BEFORE_SHOW` hook while the panel is still hidden; each showing also starts further down the callouts and summaries (`shows[id].from` / `.story`), back to the best when a game is counted. **Set Recap** joins from the second counted game. **Neither shows while the popup is up** (`statsShot.shown && setStats.available`, the players bar's own condition): the same numbers twice at once. No names, characters or score on them — the user's rule; left and right are the scoreboard's columns and a callout says whose it is. `?panel=last-game&look=<id>` holds one look for styling. **A crew battle rotates `logo-primary`, `crew-1`, `logo-sponsor`, `crew-2` only**: each crew's name and stocks left over a row per member (icon of what they last played, else their main; tag; stocks), the player in lit in the trim and the eliminated greyed (opacity on the row's contents, never the pill — the rotation commits the pill's own).
  - **Stats from the app only, oriented by start.gg player id** against the ids in each column *now*, so Switch Sides needs no refetch and a late snapshot for the previous pair fails to match instead of labelling the old record with the new names. A pair still loading shows nothing. Winner-only sets render W/L from the winner.
  - **luckystats.gg** — on the player cards, the **Lucky Rank** sits under the character, flush left, as "☘ #167" (luckystats' clover, `lucky-clover.svg`, so it reads as their rank, not a seed), and **Class** (with its badge) and **Region** (with the Region's artwork, or a pin, `lucky-pin.svg`; its rank beside the name when there is one) are boxed right of the tag. **Whatever luckystats lacks takes no room** — no rank line, no row, no box, no credit — and an image that's missing or fails to load empties its slot (a pin for a Region) rather than showing a broken image; `normalize.luckyFromResponse` turns a malformed value (a rank that isn't a whole number from 1, a blank or non-text name) into null first. The head-to-head card adds the win probability under the record: each player's percentage either side of a gradient bar whose colours meet at the left player's chance (`--prob-left-color` / `--prob-right-color` from the pack, or red/blue), and each player's **Elo** (luckystats' `elo`, its Glicko μ, rounded) under their percentage, level with the bar's caption — blank on a side luckystats has none for. It needs luckystats' matchup for exactly the pair on screen (`lucky.players`), like the record — and the card needs a record: two players who have never met get no card, projection or not. It lists the pair's newest seven sets (`H2H_SHOWN`, the app's `H2H_PILLS`). **Every card showing luckystats data carries "Powered by LuckyStats.gg" and the clover** (`.lucky-credit`, not uppercased — the name as luckystats writes it) — the endpoint was given on that condition; a card without luckystats data hides it. It sits in the panel's bottom padding, 6px off the card's edge.
  - **Rotation:** `_transitionTo()` cancels whatever is animating on the two panels and bumps `_run`, so a stale transition's `onDone` can't spawn a duplicate timer chain. **An info panel never moves; its rows are the motion.** Each visible row is a *beat* (`beatsOf`: the identity, each header, each pill, the projection, the credit — lists and `.h2h-header` open up into their rows). Beats cascade in top to bottom and out the same way, quicker, on a stagger that speeds up and is capped (`cascadeOffsets`: `CASCADE_IN` / `CASCADE_OUT`, gaps ×0.85 to a floor); the incoming rows are handed the card row by row (`handoff`: a row waits until every old row it would be drawn over has gone, measured with `getBoundingClientRect`; unmeasurable — the sandbox — waits for the whole exit). The tint is one `.panel-surface` that only fades between a logo and a panel. Logos still come and go whole (focus-pull in, drift forward out). Accents ride the cascade: header hairlines draw outward, the projection bar fills from 50% (`@property --p`), W/L edges (`::before`/`::after` bars coloured by `--edge-l`/`--edge-r`, not borders) wipe down. `stopAnims` cancels an element's own and its pseudo-elements' animations, never its children's (an `Overlay.swap` cancelled from outside never draws). A leaving panel is settled hidden by a `_busy` token once its rows have gone; a restart or take-over invalidates the token. The rotation's `onDone` is a timer, not an animation promise, so a cancelled beat can't stall it. **A slot-list change restarts the rotation only when the visible panel left the list** — `restart()` rotates from the top and slot 0 is always the logo, so restarting per change flashed the logo on every set load. `tests/side-panel.test.js` pins both halves.
  - **Render only what changed** (per-panel view comparison), and through `rotator.render()`: off screen at once; a leaving panel holds its newest render until hidden; the panel on screen tries the caller's `patch` (the crews turn a stock count in place with `Overlay.reel`) and otherwise re-cascades — rows out, redraw, rows in — so late data never pops.
  - **A card that can't be populated never comes on.** Each panel refreshes on its own (`FEEDS`); one whose data can't be read, or whose draw throws (`drawSafely`, the `BEFORE_SHOW` looks included), is emptied and **`broken`** — out of the rotation until its data changes and draws — and the rest rotate on. `_transitionTo` draws the incoming panel *before* the outgoing one leaves and, if it has nothing (`slotHasContent`), `_skip`s it: the panel up stays and the rotation moves on, never an empty card or a stalled rotation. A stats card needs something under its title — a stat, a callout or a summary (`statsView`).
  - **Long text fits before it's cut** (`fitText(node, minPx)`, synchronous — call it after the node is in the document; `rAF` never fires in a source that isn't painting), refit when web fonts land. In order: widely tracked type gives back up to half its letter-spacing; the font shrinks to `minPx`; the rest of the spacing goes; the letters are drawn up to 20% narrower (`CONDENSE_MIN`: `scaleX` on an inner `span.ov-fit`, and `.ov-condensed` turns the box's ellipsis off, since it would hide the whole span); only then the ellipsis. Text with element children skips the condense step. `Overlay.text(…, { fit: minPx })` fits as it draws. Floors are low on purpose (the side panel's 9–20px, the bracket's names 55% of their size): a whole name, small, beats half a name. Everything the bracket, side panel and scoreboard can overflow is fitted — names, round plates, Up Next headers, the title bar, the crew chip; check with `[data-fit-min]` nodes whose `scrollWidth > clientWidth` and no `.ov-condensed`. **A list's rows use `fitGroup(nodes, minPx)`, called once after the last row is appended**: the rows share the smallest fit (down to 80% of the stylesheet size; an outlier below that shrinks alone). Fitting row by row as they're appended froze sizes from a half-built list — the pills are `flex: 1` with text in `cqh`, so the first rows measure taller — and identical text came out at three sizes once the fonts were cached. The bracket's names use it too.
  - **Clip toast** slides over the bottom card's bottom edge; toasts queue (restarting a visible pill flickers on stream) and keep only the newest.
  - **Background flair** (orbs, spotlights, contours…) is the theme pack's, drawn in the bottom card's `.flair-card` slots — see Theme packs. Salty Suite's spotlights: clip-path + gradient + a horizontal mask (prefixed too) make the beam — drop any one and a flat wedge goes on stream.

## Theme packs

Every overlay links `overlay.css`, which imports the switch. All packs live in the repo at once (`hundred-acres` — on air, "Trail Map": BabyDoll type with National Park as the self-hosted fallback, fox-orange trim, firefly flair — and `salty-suite`); re-skinning is the one `@import` line, which the dock's **Setup → Theme** select rewrites (`POST /api/theme`, `setThemePack()` in `lib/server/api/setup.js`): every overlay fades out and reloads in the new pack. The choice is the file itself, so it survives a restart and shows as a git change — **switching it back afterwards is the step that's easy to forget**. A hand edit still works (then refresh the sources).

- **Two url rules in a pack.** A normal `url()` (the `@font-face src`) resolves against the pack file, so `./fonts/…`. A `url()` **inside a custom property** resolves where the `var()` is used, so `--logo-url` is written relative to an overlay stylesheet: `url("../themes/<pack>/logo.png")`. Copying a pack means editing those two paths; preflight and `tests/overlays-static.test.js` resolve them.
- `--logo-filter` / `--sponsor-filter` let a pack recolour artwork (`invert(1)` for black ink on a dark card). Logos are CSS-only (`background-image: var(--logo-url)`), never `<img>` — `getComputedStyle` returns the custom property's url verbatim.
- **`@import` must precede every other rule** in a file, or it is silently dropped.
- Fonts: the pack's brand font self-hosted; any Google Fonts fallback is a network request that fails on venue Wi-Fi.
- `--score-bg-color` is three surfaces (score boxes, the side panel's bottom card, the bracket title); `--score-box-bg` lets a pack diverge the score box alone.
- **`--trim-color` / `--trim-rgb`** — an optional second accent for small details only (the centre of every graduated top hairline, the side panel's header dividers, the bracket's live-set border). Read as `var(--trim-color, var(--text-color))`, so a pack without it is unchanged. A token no overlay reads doesn't go in a pack.
- **Background flair belongs to the pack.** A layout only provides empty slots — `<div class="flair flair-<context>">` with 8 `<i>`s: `flair-card` (side panel bottom card), `flair-title` (bracket title bar), `flair-plate` (highlights title plate) — and the pack's `flair.css` draws in them by `.flair-<context> > i:nth-child(n)`. Unused slots are `display: none`; a pack with no `flair.css` has no flair. The base rules (`overlay.css`) are wrapped in `:where()` so any pack selector beats them, though the pack loads first. **`.flair` has no z-index on purpose** — it would become a stacking context and a slot's `mix-blend-mode` (Salty Suite's beams) would blend with nothing. A pack defines its own `body.no-animate` look. Salty Suite: orbs + spotlights. Hundred Acres: fireflies, with topo contours as an option, each switched by a `--flair-*` token in its `theme.css`, plus a static "canopy light" on the title surfaces that replaces the brightness the orbs used to add. Hundred Acres' contour artwork is used as a CSS **mask** over a token fill, so it follows the palette. Two optional tokens: `--score-scale` (the scoreboard's digits, for a face that runs large — National Park wants 0.88 if it's ever made primary) and `--pill-bg` (the side panel's pills, near-solid so the fireflies don't show through the stats).
- **A variable font can be declared narrower than its axis** to raise a page's default weight: Hundred Acres declares National Park (wght 200–800) as `font-weight: 600 800`, and Chrome clamps the side panel's default 400 to a real 600 — heft without a layout asking for it.
