# The stats popup

Moved out of [CLAUDE.md](../CLAUDE.md) so it loads only when you work on this area. CLAUDE.md keeps the rules that bite from anywhere else; read them there too.

After a game, the game just played against the set so far (slippi-set-stats' numbers, plus callouts and a summary); once the set is won, the wrap-up. Read from each counted game's `.slp`, drawn by `/o/set-stats` (a 1920×1080 page; **the Players bar draws it too** — `/o/scoreboard/players` holds it in a full-frame `<iframe class="stats-frame">` above the bar, passing its `?layout=`/`?style=`/`?pack=`/`?stages=`/`?show=` through, and `?stats=0` leaves it out for a scene that keeps `/o/set-stats` as its own source; never both, or it draws twice), driven from the dock's **Stats** tab, the strip's **Stats** key and `Ctrl+Shift+G`.

```
store games ─ replay.file ─→ worker.js (game-stats.js + fun-stats.js, one file at a time, off the main thread)
                                 ↓ per-port numbers, cached per file
store.scoreboard() + cache ─→ set-view.js (pure; accolades.js, stories.js) ─→ store.setSetStats()   (`setStats`, not saved)
game counted / next game / dock / hotkey ─→ director.js ─→ store.setStatsShot()  (`statsShot`, not saved: up or down, reading, layout, seed)
dock's Stats tab ─→ store.setStatsConfig()  (`statsConfig`, saved: layout — or "auto" — style, pack, auto, delaySec, holdSec, mode, combos, pools)
```

- **`game-stats.js`** — one singles game's numbers per **port**: slippi-js's own (kills, damage, openings/kill, damage/opening, neutral wins, counter hits, inputs/min, L-cancel %) plus the biggest punish (a conversion's end − start %, attacker = `lastHitBy`), the longest combo (moves), the percent each kill came at, self-destructs (a stock lost with no opponent conversion `didKill` within 12 frames of it), stocks left, how far behind the winner ever was (`startStocks` from each player's settings — `stats.stocks` only lists stocks that began), and `fun` (fun-stats.js, below). A parse is ~0.5s, so it runs in **`worker.js`** (one long-lived worker, a queue, a 30s timeout). A file read before Slippi finished it (no game end yet) is read again once it has grown. A read that fails for a reason that can pass (a timeout — which also restarts the worker — the worker dying, a throw on a half-written file) is tried again 2s later, three times in all; a read of a shape nobody expected costs its game (`unreadable`), never the view. **A view that can't be built publishes none** (`set-view.js unavailable()`, never the last one — it may be the previous set's): Show refuses, the side panel's stats cards drop out, and a popup that's up comes down (`dropIfEmpty`, after every rebuild — the same rule as stats gone with Doubles or a cleared score). A broken art pack costs the portraits. The director's timers are guarded (a throw out of a timer ends the app).
- **`set-view.js`** — pure. A side's numbers are the ports in that column of each game's `replay.players`, which Switch Sides reverses: the stats follow the players with no re-read. Builds both readings every time (`game`, `set`) so the dock can flip between them: the ledger rows (last game, set average or best, each game), **insights** (callouts — set highs, streaks, comebacks, stats against the result, the set's earliest kill / biggest punish… — and accolades, each scored and worded for every slot a layout has: `tag`, `short` text, `long` segments, a margin `note`; `rank()` keeps one per stat, row and family per player, never three callouts or three accolades running, a title already on screen swapped for one of its alternatives, up to 12), **stories** (up to 6 summary sentences as `{ t }` / `{ em }` / `{ t, name: true }` segments — never markup; a player's name is marked by its template key, `NAME_KEYS` in `stories.js`, `who`/`opp` in an accolade's long form), and **facts**. A ± game counts in the score, not the stats (`counted` / `total`). `over` = `set-text.js`'s `setIsWon` on the best-of label on the scoreboard now (so a strip override or a rule change re-decides it; `format` carries the label). **Singles sets loaded from start.gg only**: doubles, crew battles and a set with no `setId` (typed names, or unlinked by a tag edit on the strip — a preview set counts as loaded) have no stats and say why, their replays are never read and their games start no automatic show (`index.js hasStats()`). A four-player game played while a singles set is still up (the doubles set not loaded yet) reads as `notSingles` (game-stats.js): it isn't counted — like a ± game, not as unreadable — and calls off the automatic show it started, which would otherwise put up the game before it.
- **`director.js`** — whether it's up. Manual Show / Hide / toggle at once (Hide also cancels a pending automatic show). **Auto**: a counted game (a Slippi game end recorded on the scoreboard — a ± or a handwarmer never is) puts it up `delaySec` later, so the camera gets the players' reaction first; `pendingAt` is the dock's countdown. It waits (1s retries, up to 20s) for that game's replay to be read rather than show the previous game. `holdSec` > 0 takes an automatic show down after that long. **The next game starting (`game-start`, wired in `index.js`) or another set loading always takes it down**, cancelling a pending show. Config mode `auto` reads `set` once the set is won, else `game`; `random` picks either at each show and holds it (with one game counted the two are the same, so it reads the game). **Layout `auto`** is picked here, once per show, into `statsShot.layout`, so the dock and every source agree: from `pools.mid` while the set is on, `pools.over` once it's won (`catalog.js layoutFor`), never the last one twice running when the pool has another; the set being won while it's up, or the pool losing the layout that's up, picks again. `seed` is new at each show — random poses and a random style are drawn from it, so every source draws the same and it holds while up.
- **`fun-stats.js`, `accolades.js`, `stories.js`** — the light half of the callouts. **`fun-stats.js`** (in the worker, beside game-stats) is what each port *did*, not how well: slippi-js's `actionCounts` plus one frame walk for what it doesn't count — time in shield, on the ledge, in the air and offstage, distance run, taunts, times grabbed, projectiles by item type and `owner` (replays from Slippi 3.6), shines, Rests landed, the move landed most and the one that killed, how each stock was lost — and per game `leadChanges` / `bothLastStock`. A number it can't read is null, never 0, so nothing fires on a missing count. **`accolades.js`** (pure) is the pool: per entry a number per side, a floor (`min`, and `hot` for a stronger score), how a set adds it up (`agg`), and several wordings for each slot — `tag` ≤ 20 characters, `short` ≤ 34, `note` ≤ 14, `long` ≤ 140 (`tests/set-stats.test.js` checks every wording through `allWordings()`). A seed (the set, the game, the reading) picks the wording, so consecutive games never reuse one; an accolade the same player already had this set scores lower, and so does one shown in the last three sets (`index.js` remembers them at `set-closing`, in memory only). **`stories.js`** (pure) is the summaries, the same way: facts that hold for this game or set (won neutral but not the game, a seesaw of lead changes, a ledge battle…), each in several wordings. What the Melee community calls things, and what a replay can measure (item ids, action states, death animations, nicknames to use and to avoid), is **[docs/research/melee-stat-accolades.md](research/melee-stat-accolades.md)** — read it before adding an accolade or a story.
- **`art-packs.js`** — **the art isn't in the repo**: the dock's **Setup → Art packs** downloads it in one click (`POST /api/art-packs/download`) from the GitHub releases TSH itself uses (joaorb64/StreamHelperAssets; the pack list is its `assets.json`): every Melee pack with face positions — `full` (VS-screen renders, 24 MB), `CSProject_MeleeFull` and `CSProject_AltFull` (CSProject renders, ~115 MB each), `portrait` (select-screen busts, 3 MB) — plus `stage_icon` (24 MB); icon packs and TSH's base files are skipped. Each is a `.7z` (split ones joined in order) unpacked with the **system's bsdtar** (Windows' own `tar.exe`, by full path — Git's GNU tar can't read 7z) into `overlays/assets/packs/<pack>/` (gitignored), beside the old copy and swapped in only when whole, with a `.installed.json` marker holding the release's version: the same click updates, and a failed download keeps what was there. One job at a time (a second click while the pack list is read joins it), in the background; the dock polls `GET /api/art-packs`. A part that receives nothing for 60s is given up; a swap cut off mid-way (the old copy left in `.download/<id>.old`) is put back at the next start; GitHub unreachable is asked again at most once a minute. A finished pack is drawn at once (`portraits.reload()` + a rebuild). The operator holds the rights to the art. **The VS screen pack is the exception: it's committed** (`packs/full/`, the release's 26.07.31.49734 upscaled 2× with Real-ESRGAN — its renders were drawn at ~1.55× their pixels and looked soft beside the CSProject ones). `config.json`'s eyesights are doubled with the pictures and it carries `upscaled`; `portraits.js` takes `k` from the PNG's height, so nothing else changes. Its unchanged `version` makes a clone count it as current. **A newer release in the dock's Download all replaces it with the low-res art** — `git checkout -- overlays/assets/packs/full` puts it back (re-upscale the new release before committing it).
- **`portraits.js`** — character art from those packs (`<character>_<costume>.png` + `config.json` with each character's `eyesights` — where the face is — and, in the CSProject packs, a `rescaling_factor`), placed by the face so one layout fits all 26 characters, each drawn at `NORMAL_HEIGHT` × the pack's `fill` (`art-packs.js` `KNOWN`: how much of its frame the character fills) × its rescaling factor, so every pack comes out about the same size. **Each side carries a portrait from every installed pack** (`sides[].portraits`, by id) **and each game its stage's picture from every installed stage set** (`games[].stage.pics` — a pack whose `config.json` type is `stage_icon`; the release has one Melee set today); `layouts.js` picks `statsConfig.pack` (the Stats tab's **Portraits**, or a source's `?pack=`) and the first installed stage set (a source can pin another with `?stages=`, or `none`), so a switch is a live swap with no re-read. **Anything missing falls back to what's downloaded**: a pack that isn't there (or has no picture of this character) gives way to the layout's next one, then any installed one, so the default `pack: "auto"` never draws a gap; with no stage set installed there are simply no stage pictures. **Random poses** (`pack: "random"`, `layouts.js randomPair`): a pack per side from `statsShot.seed` (new at each show, so every source agrees and it holds while up), full-body renders only (never a `cut` bust pack), both sides from one `family` of renders (`art-packs.js` KNOWN: CSProject's two pose sets are one, the VS screen's another), every drawable pair equally likely, in whatever style "auto" or the pick gives. **A mirror match never draws one pose twice**: the left side keeps the pack, the right takes the next one that has the character (the layout's pack order, then any installed), in the same style (`withPack`). Without any pack the popup has no portraits or stage thumbnails and nothing else changes. Served at `/assets/packs/`. A bust pack (`type: portrait`, cut at its frame) is marked `cut`: the overlay feathers the cut, and drops a silhouette style's plain offset outline copies, which would show through the feather as patches.
- **`overlays/set-stats/portrait-fit.js`** — **the per-pose tweaks, one quick-reference map**: pack → character (TSH's name) → `f` mirror (the art looks left; every pose is drawn looking inward — the right side's box mirrors it again; judged by face, then body), `o` (looks left but carries lettering, which can't be mirrored: that side takes the next pack — Alt DK's tie), `z` zoom about the face, `x`/`y` move the face (px at portrait scale 1, so one value means the same in every layout), `r` tilt, `e` a corrected face point, `l` a rim of light (Game & Watch on a dark window); each can be overridden per slot kind (`edge` window portraits, `card` the Players rails and Polaroids) and per layout, and a pack's `"*"` scales every character in it. Edit and refresh the source — nothing to rebuild. Tuned with **`.scratch/portrait-lab/`** (`node .scratch/portrait-lab/lab.js` → `:5088/lab`: every character at once in any layout × pack × style, a ring on each face, a list of any face under a piece of content; arrows / +− / f / [ ] edit live and print the pack's map; `/lab/poses` is a face-crop sheet per pack; `?combos=1&l=fox&r=marth` one layout in every pack × style; `shot.js` screenshots it headless, since a hidden browser pane doesn't paint). **The per-layout values fit each pose's gesture to that layout's space** (Peach's heart, Mario's peace sign, a raised fist, a sword — named in a comment on the character): the face first (the whole head clear of every piece of content, near where the layout puts it), then the hands and props out from under the glass and cards and off the portrait box's inner edge; the outer side may run off the window, and a small figure (Kirby, Pikachu) is brought up toward the layout's usual size. They come from the lab's optimiser (`?opt=1`, `opt.js` over `keys.js` — each pose's hand and prop points; `runopt.sh` runs every layout × pack, `gen.js` + `write.js` put the picks in the map, `?compare=1&probe=1` shows before | after with what's hidden marked). Each layout's best fit (`catalog.js` `LAYOUTS[].style` / `.packs`, matched in `layouts.js` — the test checks they agree) came from comparing every layout × style × pack there; `layouts.js bestFit()` is the one rule for what "auto" draws. The field notes (Margins, Ranger log) put each game's numbers inside, by the label, and the set's outside; up to three handwritten notes go in the gap between a row's label and its player's number (never over a portrait), each marked a different way (`innerNotes`: Margins an arrow, a circle, an underline; Ranger log an arrow, a star, a box), the number's strokes drawn after the words (`data-fx="draw"`).
- **`catalog.js`** — the layout and style ids (the dock lists them, the overlay draws them; `tests/set-stats.test.js` checks they agree), the config's rules and Auto's draw (`layoutFor`, `poolsOf`: a pool is known ids only; empty or missing = every layout). Old saves read forward: `layout: "random"` reads as `auto`, and a saved `stages` is dropped.

**The overlay** — `overlays/set-stats/`: `layouts.js` (pure, loads in Node too) turns `setStats` + the config into markup — eight layouts (**Spotlight**, **Players**, **Margins**, **Ranger log**, **Tale of the tape**, **Polaroids**, **Lower third**, **Condensed**), each with its own best fit, and six picture styles any layout can take (Cream duotone, Scanlines, Riso, Rim light, Ink sketch, Plain; `style: "auto"` = the layout's own, `"random"` = one drawn from the show's seed) — built with `html```, which escapes every value (the page then sets it with `innerHTML`). The callouts' long forms rotate in the layouts that have room: the Tale of the tape's **band** along its foot takes a summary, then two callouts, in turn (up to 12), each a stub — its title, number, whose it is, an arrow toward their side — beside its sentence. **Condensed** is built round the Players bar and leaves the middle clear for the cam: a bare full-frame window (`skin: "bare"`, `motion.win: "none"` — only its pieces move) of small plates round the edge — the title and summary along the top, the stage and length in the top corners, a head-to-head column standing on the round card where the logo sinks, each player's own numbers and up to two of their accolades on their name card, and a portrait in each bottom corner standing behind its card's outer end (the `.win-clip`'s `clip-path: path(evenodd, …)` cuts the cards' boxes out of it). Its positions are the Players bar's (`CZ` in `layouts.js`), so as its own source it must sit over that bar. `set-stats.js` runs one state machine, a transition at a time: down → up (the window grows up out of the players bar, portraits slide in from the window's outer edges — 26% of their width, in their own mirrored frame, the window's clip their doorway — cards, rows cascading), up → down (the same paths back, everything at once and quicker than any entrance — `CLOSE`, under a second on stream), and **up → up with anything different (layout, style, reading, new numbers) swaps the insides without taking the window down**, so the operator mixes and matches live — except into or out of a layout with **its own window box** (the Lower third, the Condensed: `win: { l, t, w, h }`), which goes down and comes back up in it (`reboxed`: no head start for the logo, already down) rather than resize a window with content in it; portraits that would draw the same stay put (only the window's: portraits inside cards — Players' rails, the Polaroids — are redrawn and slide in from their card's edge), and a layout with another skin fades its background (`.win-bg.bg-<skin>`, the skin on the background itself) in over the old one. **Each layout moves like its scene** (`LAYOUTS[].motion` — `win`, `por`, `rows`, `lead` — plus `data-fx` on its pieces, played by `set-stats.js`'s `FX`): the glass layouts rise out of the players bar with portraits sliding in through the window's edges; the field notes are printed and written, never slid (portraits uncovered from their margin, titles and margin notes written left to right with their strokes drawn after — an SVG path with `pathLength="1"` and `data-draw` — stamps pressed, ruled lines drawn down the page, the clipboard's clip settling first); the Polaroids are tossed onto the page and develop from a washed print; the Tale of the tape's fighters walk out first (`lead`) and each row's numbers close in from their own side; the Players rails stand up out of the bar carrying their portraits; the Lower third opens from its middle (clip-path) and its rows run in from the left; the Condensed's pieces come from the outside in — the centre column and each player's plates rise out of the bar's cards (`emerge`, cut off at the card's top edge until they clear it), the top band and corners come in from their nearest edge (`inward`) — and leave the same way (`FX_OUT`). A plate marked `data-carry` brings its insides with it: one entrance per container, never a cascade inside a moving plate. Share bars fill from their middle. A picture style adds its own touch in any layout (`STYLES[].pieces[].fx`: riso's second ink slides into register, a silhouette's rim catches a beat late, scan lines roll down). A swap leaves the old layout's way and arrives the new one's; cards leave without blur (glass with a backdrop-filter). Check motion with `.scratch/portrait-lab/frames.js` against the rig — every animation paused and seeked, a contact sheet of each layout's entrance and exit. **Every wait is a timer, never an animation's promise** — a source that isn't painting never finishes an animation (the side panel learned the same), and an awaited exit would leave the popup up forever. Only the leaving half of a transition is waited for; an entrance is cut into, and **an exit starts from where each element is** (`now()`: a row still waiting for its turn stays hidden — cancelling the entrance first flashed everything to full view). The window moves on transform and opacity only (no blur on a layer that size, like the bracket's boards). Portrait opacity, the wrap-up's winner/loser included, is inline, never `!important` — an animation can't override `!important`. **The players bar's logo hands off to it**: `scoreboard.js` sinks the badge into the round card (`--logo-y`, script-animated over the CSS entrance) while the popup is up, the window waits `WINDOW_IN_DELAY` for it, and on the way down the logo climbs back out `LOGO.backDelay` in, as the window clears. **Text is sized to fill its box** for the usual wordings and fits for the longest: one-line values through `Overlay.fitText`, sentences step their size down (to 60%) until they fit their box — check with the text stress rig below. **Callouts speak in four voices, the same in the popup and the side panel's stats cards**, so the text doesn't run together: the title (trim, spaced caps), the number (the score face, biggest), its line (upright, bright) and, last and quietest, whose it is (dimmer italic caps, a player's behind a dot — `.pl`; "Games 1, 2 and 3" has none); a player's name in a sentence (`.nm`) is the same italic caps. A callout card (`mini`, the Condensed's plates) uses the whole card in that order: the title across the top, the number beside its line, whose it is across the foot. Colour comes only from the pack's tokens. **A draw that throws** clears the window back to down (`reset()`) and isn't tried again until something it draws from changes (`failed`, its signature) — one bad layout would otherwise flash half a popup at every state push. `?layout=` / `?style=` / `?pack=` / `?stages=` pin a source; `?show=1` keeps it up.

**Where new looks are tried first**: `.scratch/set-stats-preview/` (gitignored; mock data, 8 popups, 4 side cards, every style) and `.scratch/set-stats-rig/` (the real dock and overlay on real replays, no start.gg/OBS/data — see docs/TESTING.md). A layout graduates by moving its `render()` into `layouts.js` and its id into `catalog.js`.

**The text stress rig** — `PORT=5079 node .scratch/set-stats-rig/stress.js`, then `node .scratch/set-stats-rig/stress-run.js <outDir>` (Chrome headless; `--layouts`, `--modes` narrow it). It loads real replays as whole sets with long names and round, the widest numbers (`extreme`) and every callout in the pool's longest wordings (`worst`) — scenarios long, extreme, worst, v1–v3 and one — and runs every layout in both readings, writing a screenshot of each and listing any text that's cut, overflows its box or falls under 12px (`probe-text.js`, grouped by `issues.js`). Run it after changing a layout's text or the pool's wordings; it should list nothing.
